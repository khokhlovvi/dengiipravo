# Задача: публикация в общий чат по запросу участника

Разбор 27.11.2026 по ситуации с Адамом. [[Мараев Адам Хож-Ахмедович|Адам]] попросил бота опубликовать информацию в общий чат (тема General), но бот отказал: такого сценария нет. Разобрали по документации хранилища и README бота на сервере, как публикация устроена сейчас, и зафиксировали решение Владимира, каким должен быть новый сценарий. Бот — [[11 Бот базы знаний]].

## Главное

Бот умеет публиковать в общий чат, но только через закреплённые сценарии; произвольного сообщения по просьбе участника нет — это по замыслу, а не поломка. Решение Владимира 27.11.2026: добавить сценарий «черновик + кнопка» с двумя обязательными свойствами — каждый черновик сразу пишется в хранилище, а клиентская информация раскладывается по проектам (/lk, /firms), как у CVR. Анонс команде отправлен в тему General 27.11.2026 ([[Анонс в общий чат — публикация через бота]]). Оценка реализации по коду на сервере — ниже: новая инфраструктура не нужна, объём небольшой.

## Как публикация устроена сейчас

| Сценарий | Как запускается | Куда |
|---|---|---|
| Минутка встречи с чек-листом задач | Кнопка «📣 Опубликовать в общем чате» под ответом бота в личке; нажать может только участник | Тема «Задачи и минутки летучек» |
| CVR по клиенту | Только по кнопке и только кратким анонсом; полный CVR в чат не уходит | Общий чат |
| Утренняя сводка открытых задач | Автоматически в 09:05 (digest.py) | Тема «Задачи и минутки летучек» |
| Итоги недели | Автоматически по воскресеньям в 17:00 (dip-weekly-summary) | Тема General |
| Новостной дайджест | Автоматически ежедневно в 08:00 (news-parser) | Тема «Новости» |
| Произвольный текст по просьбе участника | Нет такого сценария | — |

В самом общем чате бот молчит и в разговоры не вступает.

## Решение Владимира 27.11.2026: как делать

1. **Черновик + кнопка.** Участник пишет в личке «опубликуй в общий чат: …». Бот причёсывает текст до короткого анонса, показывает черновик и под ним кнопку «📣 Опубликовать»; нажать может только участник проекта. В опубликованном сообщении — отметка, от кого публикация; Владимиру — уведомление в личку (канал NOTIFY_WRITES). Тема по умолчанию — General, бот спрашивает, если неясно.
2. **Черновик сразу в хранилище.** При создании черновика бот сразу записывает его в базу (коммит «База (Имя): …»), до всякой публикации: тексты не должны жить только в Telegram. После нажатия кнопки запись дополняется фактом публикации — чат, тема, id сообщения.
3. **Клиентская логика — как у CVR.** Если публикация касается конкретного клиента, информация записывается в проект: лизинговые компании — карточка в разделе [[14 Лизинг и коммерческая недвижимость]] и инструмент /lk (API dip-lk-api, ~/vaults/dip-lk), юрфирмы — онлайн-таблица /firms ([[Рассылка региональным юрфирмам]]). Правило CVR сохраняется: в чат уходит только краткий анонс, полные данные по клиенту — не уходят.
4. **Сомнения — уточняющие вопросы.** Если неясно, о каком клиенте речь (название совпадает, неполное название, несколько кандидатов), бот не публикует и не пишет в базу, а переспрашивает уточняющими вопросами с дополнительной информацией о клиенте (название, город, контакт, чем занимается), как уже делает с задачами без ответственного (#уточнить). Только после однозначного ответа — черновик и запись.
5. **Документация.** Обновить /help, [[Памятка о боте для команды]] и [[11 Бот базы знаний]].

## Оценка реализации (27.11.2026, по коду на сервере)

Смотрели код на сервере: bot.py (659 строк), meetings.py (202), common.py (198), lk.py (382). Вывод: новый сценарий собирается из уже существующих приёмов, новая инфраструктура не нужна.

**Что уже есть и переиспользуется:**

- Маркеры в ответе модели: `ВСТРЕЧА:` → кнопка p:<хеш> публикации минутки, `ДОКУМЕНТ:` → сборка PDF и Word. Новый маркер `ПУБЛИКАЦИЯ:` — тот же приём.
- Кнопки и их обработчики: handle_callback уже разбирает p:, g:, t:, a:, n: — добавляем тип q:.
- Запись в базу до публикации — уже норма: модель пишет заметку, бот коммитит «База (Имя): …» (handle_message + commit_push + guard отката чужих правок).
- Отправка в чат — common.tg/send; уведомление Владимиру — notify_write (NOTIFY_WRITES).
- Уточняющие вопросы при неоднозначности — уже норма поведения модели по системному промпту (как с задачами без ответственного).

**Что добавить (порядка 100–150 строк):**

1. bot.py: маркер `ПУБЛИКАЦИЯ: <путь к заметке-черновику>` в конце ответа; черновик держать в state.json (текст анонса, автор, путь заметки — переживает перезапуск бота); под ответом — кнопка «📣 Опубликовать в General» с callback q:<хеш>.
2. Новый модуль announce.py (около 60 строк): publish_draft() — sendMessage в общий чат без message_thread_id, то есть в тему General (meetings.where() всегда подставляет thread 482 «Задачи и минутки летучек» и не подходит; отправка без thread проверена 27.11 на анонсе, message_id 1125). После отправки — запись факта публикации обратно в заметку-черновик и коммит, снятие кнопки, подтверждение автору, уведомление Владимиру.
3. handle_callback: обработчик q: под vault_lock, нажать может только участник (person()), по образцу p:.
4. Промпт: в системный промпт и/или «Правила бота» — сценарий: найти клиента по «14 Лизинг…» и «07 Партнёры/Рассылка региональным юрфирмам», при неоднозначности — уточняющие вопросы; черновик записать заметкой сразу; последней строкой ответа `ПУБЛИКАЦИЯ: <путь>`.
5. Клиентские записи: для ЛК модель пишет карточки в «14 Лизинг…», для юрфирм — заметки проекта «07 Партнёры/Рассылка региональным юрфирмам»; чем питаются веб-инструменты /lk (lkapi, отдельное хранилище ~/vaults/dip-lk) и /firms (dengiipravo.ru/firms) — проверить при реализации, чтобы записи сразу отображались #уточнить

**Тонкости:**

- callback_data в Telegram до 64 байт — хеш в 10 символов, как у минуток, подходит.
- Произвольный текст участника экранировать под parse_mode HTML или отправлять plain text.
- Кнопка живёт в state.json — черновик не должен теряться при перезапуске; старым черновикам — срок жизни.
- Тестирование — на копии бота без Telegram, как делали для форматов файлов 11.11.

**Оценка труда:** одна итерация «код + промпт» вечернего масштаба плюс прогон тестов на копии. Новых сервисов, библиотек и токенов не требуется — только stdlib, как сейчас.

## Вопросы #уточнить

- Куда складывать черновики без клиентской привязки: отдельная папка (например, журнал публикаций) или блоки в тематических заметках #уточнить
