# Задача: публикация в общий чат по запросу участника

Разбор 27.11.2026 по ситуации с Адамом. [[Мараев Адам Хож-Ахмедович|Адам]] попросил бота опубликовать информацию в общий чат (тема General), но бот отказал: такого сценария нет. Разобрали по документации хранилища и README бота на сервере, как публикация устроена сейчас, зафиксировали решение Владимира и в тот же день реализовали сценарий на сервере. Бот — [[11 Бот базы знаний]].

## Главное

Бот умеет публиковать в общий чат, но только через закреплённые сценарии; произвольного сообщения по просьбе участника не было — это был пробел, а не поломка. Решение Владимира 27.11.2026: сценарий «черновик + кнопка» — каждый черновик сразу пишется в хранилище, клиентская информация раскладывается по проектам (/lk, /firms), как у CVR, при сомнениях бот переспрашивает. Анонс команде отправлен в тему General ([[Анонс в общий чат — публикация через бота]]). Реализация — в разделе ниже, служба dip-bot перезапущена.

## Как публикация устроена сейчас

| Сценарий | Как запускается | Куда |
|---|---|---|
| Минутка встречи с чек-листом задач | Кнопка «📣 Опубликовать в общем чате» под ответом бота в личке; нажать может только участник | Тема «Задачи и минутки летучек» |
| CVR по клиенту | Только по кнопке и только кратким анонсом; полный CVR в чат не уходит | Общий чат |
| Утренняя сводка открытых задач | Автоматически в 09:05 (digest.py) | Тема «Задачи и минутки летучек» |
| Итоги недели | Автоматически по воскресеньям в 17:00 (dip-weekly-summary) | Тема General |
| Новостной дайджест | Автоматически ежедневно в 08:00 (news-parser) | Тема «Новости» |
| **Произвольное сообщение по просьбе участника (с 27.11.2026)** | Просьба в личке → черновик заметкой в базе → кнопка «📣 Опубликовать в General»; нажать может только участник | Тема General |

В самом общем чате бот молчит и в разговоры не вступает.

## Решение Владимира 27.11.2026: как делать

1. **Черновик + кнопка.** Участник пишет в личке «опубликуй в общий чат: …». Бот причёсывает текст до короткого анонса, показывает черновик и под ним кнопку «📣 Опубликовать в General»; нажать может только участник проекта. В опубликованном сообщении — отметка, от кого публикация; Владимиру — уведомление в личку (канал NOTIFY_WRITES). Тема по умолчанию — General, бот спрашивает, если неясно.
2. **Черновик сразу в хранилище.** При создании черновика бот сразу записывает его в базу (коммит «База (Имя): …»), до всякой публикации: тексты не должны жить только в Telegram. После нажатия кнопки запись дополняется фактом публикации — чат, тема, id сообщения.
3. **Клиентская логика — как у CVR.** Если публикация касается конкретного клиента, информация записывается в проект: лизинговые компании — карточка в разделе [[14 Лизинг и коммерческая недвижимость]] и инструмент /lk (API dip-lk-api, ~/vaults/dip-lk), юрфирмы — онлайн-таблица /firms ([[Рассылка региональным юрфирмам]]). Правило CVR сохраняется: в чат уходит только краткий анонс, полные данные по клиенту — не уходят.
4. **Сомнения — уточняющие вопросы.** Если неясно, о каком клиенте речь (название совпадает, неполное название, несколько кандидатов), бот не публикует и не пишет в базу, а переспрашивает уточняющими вопросами с дополнительной информацией о клиенте (название, город, контакт, чем занимается), как уже делает с задачами без ответственного (#уточнить). Только после однозначного ответа — черновик и запись.
5. **Документация.** Обновить /help, [[Памятка о боте для команды]] и [[11 Бот базы знаний]].

## Реализация (27.11.2026)

Код на сервере ~/automations/dip-bot. Перед правками — резервная копия bot.py.bak-2026-11-27-publish.

- **Новый модуль announce.py.** Маркер `ПУБЛИКАЦИЯ: <путь к заметке>` в конце ответа модели; черновик берётся из раздела «## Анонс в чат» заметки (вики-ссылки разворачиваются в текст, **жирный** — в HTML, остальное экранируется) и хранится в drafts.json (переживает перезапуск). publish_draft() отправляет сообщение в общий чат без message_thread_id — тема General; после отправки дописывает в заметку раздел «## Опубликовано в чат» (время, кто нажал, id сообщения), снимает черновик и уведомляет Владимиру. Повторная публикация уже отмеченного черновика отклоняется.
- **bot.py.** Обработка маркера в handle_message (кнопка «📣 Опубликовать в General», callback q:<хеш> — до 64 байт), обработчик q: в handle_callback под vault_lock, нажать может только участник; в справку (/help) добавлен пункт про публикацию; в системный промпт добавлен сценарий: найти клиента поиском, при неоднозначности — уточняющие вопросы, черновик заметкой с разделом «## Анонс в чат», маркер последней строкой.
- **Тест** (/tmp/test_announce.py, без Telegram и без настоящего хранилища — отправка заглушена): register/publish_draft, экранирование HTML, взятие только раздела анонса, дописывание факта публикации, отказ при повторе, неизвестный хеш, три варианта маркер-строки — все пункты ok. Реальный чат тестом не трогали.
- **Запуск.** Служба dip-bot перезапущена, в логе «bot started», все участники на месте.

**Оценка труда подтвердилась:** около 150 строк нового кода плюс правки промпта, новых сервисов и библиотек не потребовалось.

## Решения по дополнительным вопросам (Владимир, 27.11.2026)

1. **Прямая отправка без кнопки для Владимира — не делать.** Кнопка у всех, включая Владимира: одна механика и защита от случайной отправки; для срочных случаев у Владимира остаётся серверный путь (как анонсы 27.11). Триггер «сразу» не добавляем, пока не понадобится.
2. **Отзыв опубликованного — отложено.** Бот может удалять свои сообщения, id хранится в заметке черновика; случай редкий, пока достаточно ручного удаления администратором чата. Если начнёт требоваться — команда в личке «удали публикацию» по id из заметки.
3. **Место для черновиков без клиентской привязки — папка «17 Публикации».** Журнал публикаций, имя «ГГГГ-ММ-ДД Название»; клиентская информация по-прежнему пишется в карточки проектов, в журнале — ссылка на карточку. Тестовый черновик 27.11 перенесён из «01 Входящие» в «17 Публикации»; папка добавлена в системный промпт бота 27.11 (служба dip-bot перезапущена).
4. **Чем питается онлайн-таблица /firms — выяснено 27.11 по коду на сервере (~/automations/dip-firms).** Основа `data/firms.json` загружается скриптом `scripts/publish.py --upload` на Маке после конвейера yurfirmy; записи контактов `data/cvr.json` собираются скриптом `scripts/publish_cvr.py --upload` из «16 CVR/» хранилища, привязка к фирме — по ИНН или сайту из карточки клиента в «03 Люди и компании/», иначе по названию; правки команды через личную ссылку — `data/edits.json` (предыдущие версии в `data/backups/`). Вывод: боту достаточно записать информацию в хранилище (карточку или CVR) — в таблицу /firms она попадёт пайплайном на Маке, отдельных действий бота не нужно; аналогично карточки ЛК питают /lk через хранилище ~/vaults/dip-lk.
